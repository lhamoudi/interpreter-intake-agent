02 The use case

The front door is the upgrade

I was previously embedded with a large interpretation provider's dev team — we built their IVR intake and the overflow routing behind it. The routing is smart; the intake in front of it is a fixed-path, DTMF-only IVR: one intent at a time, menu by menu.

A conversational agent takes every intent at once, in any order:

"I need a Spanish-to-English interpreter, male, for a doctor visit — and I need them immediately."

Captured, confirmed, and routed in one turn. That speed matters to the clinicians, lawyers, and community workers standing next to someone they can't talk to. And in this product, the handoff is the product — so complete capture is non-negotiable.

In-flight state lives in-process on one always-on machine, by design. Durable state → Turso. Cross-call memory → a salted hash of the caller's number, which is what makes "welcome back" work. Fronted by a Cloudflare-managed domain, DNS-only.

04 LLM integration

The model proposes. The server decides.

Claude fills intake slots through typed tools — but it never decides the intake is done. A deterministic server-side gate (checkComplete vs REQUIRED_SLOTS) is the only thing that permits handoff. Completeness is code, not model judgement.

tools

record_intake — partial slot updates, merged server-side
choose_service_tier — AI / human / video
request_handoff — validated, then live transfer
decline_request — graceful exit for non-leads

edge cases

Hang-up mid-flow → partial persisted as abandoned
Changed answer → confirmed, never silently overwritten
Out-of-scope question → declined, steered back — no guessing
Spam / wrong number → decline_request, audited

05 Product sense

Three tiers, priced like the real business

Once the intake is complete, the agent offers the caller a choice — modelled on the actual unit economics of an interpretation network.

AI interpreter lowest cost

Offered now; live bidirectional interpretation is roadmap — today it routes to a human so no caller is stranded.

Human interpreter premium

Live transfer on this call, straight into Flex. Best for sensitive or complex matters.

Video room webrtc

A real Twilio Video room per request, join link emailed. Screenshare a form or letter — and PSTN per-minute cost drops away.

Any failure on the video path falls back to a human — the caller never dead-ends.

06 Human handoff

Live transfer into Flex — with the context attached

  1. Server sets session.pendingHandoffData with the full lead as task attributes.
  2. TAC emits the ConversationRelay end message after the agent's final words.
  3. ConversationRelay POSTs it to the <Connect action> URL — a Studio Flow.
  4. The Flow's Send-to-Flex widget creates the TaskRouter task; an interpreter accepts the live call.

The platform subtlety: in voice-only mode TAC's convenience helper createStudioHandoffTool throws — the documented path is the pendingHandoffData mechanism above. Set a property, don't call a helper. Easy to miss; worth knowing.

07 Honest scoping

What fought back

A2P 10DLC error 30034

Carriers block unregistered SMS outright. The video link moved to email, and the cross-channel bonus is gated on toll-free verification. On telephony, compliance is architecture.

Mid-call language switch

STT switched; TTS needed per-locale <Language> voices; the model kept writing English. Three separate layers. Parked deliberately — two working features beat five broken ones.

Hosting risk — designed out

Fastify can't bind a port on Workers, so TAC would need porting. Chose Fly.io instead: the stock server runs unmodified. Removed the risk with a decision, not a gamble.
