02 Demo agenda

What we'll showcase

  2. Completeness check - Claude fills in the details, but server code decides when the intake is actually done.
  3. Tiered options + live Flex handoff - pick a tier, watch the task land in Flex.

  6. Graceful decline - a clear non-customer caller gets a clean hangup, with disposition logged.
03 The use case

Conversational intake in front of the routing

I was previously embedded with a large interpretation provider's dev team, building their IVR intake and the overflow routing behind it. The intake in front of that routing is a fixed-path, DTMF-only IVR: one intent at a time, menu by menu.

A conversational agent takes every intent at once, in any order:

"I need a Spanish-to-English interpreter, male, for a doctor visit - and I need them immediately."

Captured, confirmed, and routed in one turn. That speed matters for time-sensitive intake - a medical emergency, a legal urgency, a police encounter. The handoff to a human is the actual goal, so the intake needs to gather everything before that happens.

05 LLM integration

Server code decides when the intake is complete, not the model

Claude fills intake slots through typed tools, but it doesn't decide on its own that the intake is done. A server-side check - checkComplete against REQUIRED_SLOTS - is the only thing that's allowed to trigger a handoff.

tools

record_intake - partial slot updates, merged server-side
choose_service_tier - AI / human / video
request_handoff - validated, then live transfer
decline_request - graceful exit for non-leads

edge cases

Hang-up mid-flow → partial persisted as abandoned
Changed answer → confirmed, never silently overwritten
Out-of-scope question → declined, steered back - no guessing
Spam / wrong number → decline_request, audited

06 Product sense

Three service tiers

Once the intake is complete, the agent offers the caller a choice - modelled on the actual unit economics of an interpretation network.

AI interpreter lowest cost

Offered for illustrative purposes; live bidirectional interpretation is a roadmap item - so it just routes to a human for now.

Human interpreter premium

Live transfer on this call, straight into Flex. Best for sensitive or complex matters.

Video room still premium without PSTN costs

A real Twilio Video room per request, join link emailed. Screenshare a form or letter, and there's no PSTN per-minute cost.

Any failure on the video path falls back to a human.

07 Human handoff

Live transfer into Flex - with the context attached

When the caller picks the human tier, the full intake travels with the call as Flex task attributes. The caller stays on the line the whole time - a live transfer, not a callback - and an interpreter in Flex accepts the call.

In the eventual solution, the advanced routing and overflow logic would engage to find the best-fit agent - whether staffed or via the partner "crowd".

08 Honest scoping

The hard parts

SMS verification

SMS needed 10DLC/toll-free verification, which blocked the cross-channel bonus (Conversation Orchestrator resuming over SMS). The video link moved to email instead.

Mid-call language switch

Automatic language detection didn't work well off the bat. English speech-to-text often garbles someone's first sentence in another language, so the model can't reliably tell what they're speaking. Fixing that properly needed more research than the take-home window allowed. Instead: the caller asks explicitly to switch languages - and that choice is remembered on later calls.

Hosting

Fastify can't bind a port on Cloudflare Workers, so TAC would need porting. Chose Fly.io instead: the stock server runs unmodified, so there was nothing to port.

09 Future state

Interpreter Routing with Partner "Crowd" Overflow

This intake agent is the front door. Behind it sits the routing and overflow network that finds the interpreter - in-house first, then partner "crowd" capacity when in-house can't fill.
